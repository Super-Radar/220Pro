# CTSAI-A100 室内小推车 MTI 案例设计

## 目标与边界

本案例面向校园室内走廊和实验室门口的低速小推车/纸箱目标，提供一套可以在 GNU Octave 11.3.0 中完整复现的 LFMCW、距离 FFT、距离—多普勒 2D-FFT 和 MTI 静态杂波抑制实验。全部代码使用 MATLAB 兼容的 `.m` 文件，只依赖 Octave 自带功能和免费的 `signal` 包。案例同时使用 2026-08-02 采集的 CTSAI-A100 ADC、RawTarget、TraTarget 和 CAN ASC 数据，但严格区分“教学仿真”和“硬件实测”。

实测 ADC 缺少完整的调频斜率、采样率、chirp 时序、DDMA 相位编码等可验证硬件参数。因此，ADC 结果只展示采样幅度、距离 bin、归一化多普勒 bin、静态分量和 MTI 前后变化，不把多普勒 bin 强行换算为物理速度。真实目标的距离和运动趋势主要由雷达输出的点云/跟踪 CSV 展示。零字节视频、失败的 `retry2` ADC 和现有 `RadarToolsConfig.ini` 修改不进入项目。

## 方案选择

可选方案有三种。第一种是直接修改官方 ADC 示例并把所有分析散布在原目录中，改动少，但违反 Community Project 应独立组织的贡献约定。第二种是只写仿真，不携带实测数据，提交轻量，但无法满足 Issue #8 的实测对比要求。第三种是建立自包含的 `community/projects/a100-indoor-cart-mti/`，在项目内放置加载器、仿真、实测处理、测试、数据清单和结果，同时仅在确有必要时给官方加载器提供最小修复。

采用第三种方案。项目入口 `run_all.m` 依次运行仿真、参数扫描、ADC 分析和点云轨迹分析；每个模块也可以单独运行。数据目录保存四组有效 ADC 和四组点云/CAN 数据，使用清单记录场景、源文件、大小和 SHA-256，保证未误收 `retry2` 或零字节视频。所有生成图使用固定随机种子、固定坐标轴和无界面绘图，便于 CI 或无图形桌面的 Octave 复现。

## 数据流与组件

ADC 加载器先解析三个头字段：通道号、每 chirp 的 1024 个样本、256 个 chirp。随后验证 32 位打包字数量应为 `1024×256/2=131072`。本批文件还带有一个尾部零填充，只有确认所有多余字段均为零时才允许截取。每个 32 位无符号字按高 16 位在前、低 16 位在后的顺序拆成两个有符号样本，再 reshape 为 `1024×256`。短文件、头字段不符、非零尾部或非有限数值都应报错。

仿真模块在复基带生成线性调频发射信号、延时和多普勒目标回波、去斜差频矩阵，并叠加多个静止墙面/门框散射体和白噪声。快时间 FFT 得到距离谱，慢时间 FFT 得到距离—多普勒图。MTI 使用可配置阶数的脉冲间差分；结果同时给出二维图和零多普勒附近的抑制度指标。参数实验分别改变带宽、chirp 时宽、PRF、目标速度、目标数量和 MTI 对消阶数，每次只改变一个变量。

点云解析器容忍 RadarTools CSV 中穿插的 `START`、时间戳和状态行，只接受字段数与表头一致、关键数值字段可解析的目标记录。输出按采集顺序绘制目标距离、速度和 XY 轨迹，并报告有效记录数量及稳健统计量。ADC 和点云通过场景清单关联，而不是假定两类文件逐帧同步。

## 错误处理与验证

测试使用临时合成 ADC 文件覆盖正确头部、尾部零、错误头部和非零多余字段；用已知正弦目标验证 FFT 峰值和 MTI 对零多普勒的抑制；用最小 RadarTools CSV fixture 验证混合行解析。实测数据运行时再次核对文件名、字节数、SHA-256、ADC 头和维度。完成后以 Octave 无界面模式运行全部测试及 `run_all.m`，检查每张 PNG 非空，并搜索提交内容，确认没有 `retry2`、零字节视频和 `RadarToolsConfig.ini`。
