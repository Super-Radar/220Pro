# ADC 导入与连续采集可靠性设计

## 背景

RadarTools 新版会话目录中的 ADC 文件以 `Rx 通道号,采样点数,chirp 数` 三项元数据开头，并在采样序列末尾保留一个零值结束项。现有 `load_adc_data.m` 将整份文件直接当作采样数据，再按配置长度从尾部截断。这会把三项元数据送入信号处理链，并丢弃末尾的真实采样值。旧版平铺文件没有三项头字段，但同样可能包含零值结束项。

现场连续采集还发现，RadarTools 完成一次单通道 ADC 采集后，下一次操作可能没有创建新目录。仓库只包含上位机二进制程序，没有能够修复状态机的源代码，因此本次改动只能给出可验证的操作边界，不能声称修复 RadarTools 本体。

## 设计

新增独立的 ADC 文件读取函数。函数根据文件长度、Rx 通道范围以及配置中的 `rng_nfft`、`nchirp` 共同识别新版文件头，移除头字段后再处理可选的末尾零值。最终样本数必须严格等于 `(rng_nfft / 2) * nchirp`；数量不足、存在无法解释的额外值或文件头与配置冲突时立即报错，不再补零或盲目截断。

`load_adc_data.m` 只负责组织多通道矩阵和后续定点数转换，原有输出维度保持不变。回归测试分别覆盖新版带头文件、旧版无头文件、错误长度和配置冲突，并使用 GNU Octave 执行。采集文档增加连续采集检查：动作开始前必须确认新的保存目录已经创建；若按钮无进度且目录未生成，应关闭 ADC 子窗口并正常重启 RadarTools，失败动作不得标为有效样本。

## 验收条件

- 新旧两种 ADC 文件都只返回真实采样序列；
- 头字段和末尾结束项不会进入 FFT 输入；
- 异常文件以明确错误终止；
- 仓库示例文件和合成回归测试均通过；
- 文档不暗示已修改闭源 RadarTools 二进制程序。
