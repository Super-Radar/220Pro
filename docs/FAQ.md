> 如有疑惑欢迎前往社区论坛发帖提出您的问题!

### RadarTools 点击 Start 后没有数据显示？

请检查：

* 雷达是否正常供电。
* CAN-H / CAN-L 是否接反。
* USB-CAN FD 驱动是否安装成功。
* 设备管理器中是否识别 USB-CAN FD 设备。
* 上位机参数配置是否正确。
* 雷达是否处于正常工作状态。

###  设备管理器看不到 USB-CAN FD 设备？

请检查：

* USB 数据线是否正常。
* USB-CAN FD 盒是否连接电脑。
* 驱动是否按系统位数正确安装。
* 是否需要重新插拔设备。
* 是否需要更换 USB 接口。

### 上位机能启动，但没有目标点？

请检查：

* 雷达前方是否有有效目标。
* 雷达安装方向是否正确。
* 波形模式是否适合当前测试距离。
* 是否存在遮挡。
* 是否处于过近或过远的测试距离。
* 是否已经正确点击 `Start`。

### 首次连接 CTSAI-A100 后没有数据，如何进行完整排查？

首次连接时，容易把供电、CAN 接线、USB-CAN FD 驱动、RadarTools 配置和测试场景混在一起检查。建议按照“雷达供电 → CAN 接线 → 驱动识别 → RadarTools 配置 → 测试场景”的顺序排查。上一层没有确认之前，不要反复修改下一层参数。

**安全提示：**剥线、重新插线或调整端子前，应先断开电源。不要让裸露导体相互接触，也不要触碰电源适配器的市电输入部分。线束用途应以实物标签和当前设备文档为准，不要只根据线的颜色判断。

更完整的接线和软件启动说明可参考：

* [设备连接与环境搭建](./产品简介/设备连接与环境搭建.md)
* [RadarTools 安装部署](./RadarTools/安装部署.md)

#### 1. 确认雷达是否真正获得供电

USB-CAN FD 的 `PWR`、`SYS` 等指示灯亮，只能说明 USB-CAN FD 本身已经工作，不能据此判断雷达是否已经获得供电。

请依次检查：

1. 确认使用的直流电源符合当前设备文档要求。
2. 根据线束标签确认电源正极和 `GND`。不同线束可能使用 `VCC`、`VBAT` 等不同标识，应以实物为准。
3. 确认电源正极连接雷达电源正极，电源负极连接 `GND`，没有接反。
4. 确认导线已经剥出足够长度的铜芯，接线端子夹住的是铜芯而不是绝缘层。
5. 轻拉每根线，确认导线不会从端子中脱落。
6. 在熟悉万用表操作的前提下，先测量电源输出端，再测量雷达侧电源正极与 `GND` 之间的电压。

测量直流电压时，黑表笔接 `COM`，红表笔接 `VΩ`，旋钮选择合适的直流电压档；红表笔测电源正极，黑表笔测 `GND`。如果不熟悉万用表操作，应请有经验的人员协助。

如果电源输出端有电压，而雷达侧没有电压，优先检查：

* 铜芯是否插到底；
* 接线端子是否夹紧；
* 正极和负极是否接入了正确位置；
* 端子内部的导通关系是否理解正确。

本次实际排查中，一个容易误判的地方是双排直通端子的内部连接关系。不要默认所有插孔互通，也不要仅凭插孔排列判断导通方向。应在断电状态下查阅端子说明，或使用万用表通断档确认。

如果在同一条已导通回路的两个点之间测量电压，读数接近 `0 V` 并不代表没有供电，因为两点可能处于相同电位。判断雷达供电时，应测量电源正极与 `GND` 之间的电压。

雷达是否带指示灯、指示灯如何显示，可能随硬件版本不同而变化。排查供电时，应以实际电压测量结果为主要依据。

#### 2. 检查 CAN-H 与 CAN-L 是否来自同一组信号

部分线束可能同时带有 `PCAN-*`、`VCAN-*` 或其他 CAN 信号标识。不要因为线的颜色接近，就把不同组的 H、L 信号混在一起。

例如，当前使用的是 `PCAN` 组时，应成对连接：

```text
PCAN-H  →  USB-CAN FD 对应通道的 H
PCAN-L  →  USB-CAN FD 对应通道的 L
```

不要将 `PCAN-H` 与 `VCAN-L` 配成一对。如果当前线束使用其他名称，也应遵循“同一组 H/L 成对连接”的原则，并以线束标签为准。

#### 3. 检查 CAN-H、CAN-L 和接线端子

确认雷达侧 CAN-H 连接 USB-CAN FD 对应通道的 H，CAN-L 连接对应通道的 L，并检查：

* 实际接线通道与 RadarTools 中选择的 CAN 通道一致；
* 电源线没有误接入 CAN 端子；
* 多股铜线已经拧紧并可靠夹住；
* 没有散开的铜丝接触相邻端子；
* 采用弹簧夹端子时，导线已经按端子的正确方式插入并夹紧。

USB-CAN FD 端子可能还包含其他引脚，不要把中间端子直接当作雷达的电源或地。具体引脚定义应以当前 USB-CAN FD 手册为准。

如果怀疑 CAN-H 与 CAN-L 接反，应先断电，再对照线束标签和端子标识重新确认。终端设置应遵循当前设备文档和实际总线拓扑，不要在缺少依据时反复切换。

#### 4. 确认 USB-CAN FD 驱动和设备识别正常

将 USB-CAN FD 连接到 Windows 电脑后，打开设备管理器检查：

* 设备是否已经被系统识别；
* 是否出现未知设备；
* 设备图标是否带黄色感叹号；
* 设备名称和驱动状态是否正常。

如果设备没有正常识别，可以依次尝试：

1. 重新安装与当前 Windows 系统匹配的驱动；
2. 重新插拔 USB-CAN FD；
3. 更换电脑 USB 接口；
4. 检查或更换能够传输数据的 USB 连接线；
5. 重新打开设备管理器确认状态。

`PWR`、`SYS` 等指示灯正常，通常只能说明 USB-CAN FD 已经供电并运行。是否已经建立 CAN 通信，还应结合 CAN 通道状态、接收数据和软件提示判断，不能仅凭某一盏灯下结论。

#### 5. 检查 RadarTools 的设备、通道和配置

硬件连接和驱动确认正常后，请继续检查：

* RadarTools 是否选择了正确的 USB-CAN FD 设备；
* 软件选择的 CAN 通道是否与实际接线通道一致；
* 通信模式和参数是否来自当前版本官方配置或已经验证的工程配置；
* 是否已经启动设备并开始接收数据；
* 软件是否报告设备打开失败、通道初始化失败或数据解析异常。

通信参数可能随固件、配置文件或软件版本变化，因此 FAQ 不固定给出具体数值。

判断时可以把问题分成两类：

* **完全没有 CAN 数据：**返回检查雷达供电、CAN-H/CAN-L、设备通道、驱动和终端设置。
* **已经收到 CAN 数据，但 RadarTools 没有目标：**重点检查 RadarTools 参数、数据类型选择和测试场景。

#### 6. 确认测试场景中存在有效目标

即使供电和通信都正常，测试区域内没有有效目标时，RadarTools 也可能没有目标信息。首次验证建议：

1. 让雷达正面朝向待测区域；
2. 确认雷达前方没有明显遮挡；
3. 让人员在雷达前方移动，作为容易观察的验证目标；
4. 不要只使用很小、完全静止或位置不明确的物体作为第一次验证目标；
5. 确认目标位于当前安装方向覆盖的区域内；
6. 确认当前工作模式适合测试场景。

如果人员移动后仍没有目标，但软件已经能够接收 CAN 数据，应保存 RadarTools 配置截图和接收日志，再检查数据解析或雷达配置。

### 首次连接时有哪些常见误区？

| 常见误区 | 正确认识 |
|---|---|
| USB-CAN FD 的 `PWR`、`SYS` 亮，说明雷达已经供电 | 只能说明 USB-CAN FD 本身工作；雷达供电应在雷达侧电源正极与 `GND` 之间测量 |
| 红线一定是正极，某种颜色一定是地 | 线束应以实物标签和测量结果为准，颜色只能辅助判断 |
| 双排接线端子的所有插孔全部互通 | 不同端子的内部结构可能不同，应在断电状态下查阅说明或测量导通关系 |
| 在同一导通回路的两个点之间测到 `0 V`，说明没有供电 | 两点处于相同电位时，测到 `0 V` 属于正常现象 |
| `PCAN-H` 可以搭配任意 CAN-L | H、L 必须来自同一组 CAN 信号 |
| CAN 通道指示灯不亮，说明雷达没有上电 | 雷达供电和 CAN 通信是两条独立链路，应分别检查 |
| RadarTools 没有目标，说明硬件损坏 | 也可能是通道、参数、安装方向、遮挡或测试区域内没有有效目标 |

### 推荐的最短排查路径是什么？

```text
测量雷达侧电源正极与 GND
    │
    ├─ 无电压 → 检查电源、剥线、端子和正负极
    │
    └─ 有电压
         │
         ├─ Windows 未识别 USB-CAN FD → 检查驱动、USB 线和接口
         │
         └─ Windows 已识别
              │
              ├─ 没有 CAN 数据 → 检查同组 CAN-H/L、使用通道和终端设置
              │
              └─ 已有 CAN 数据
                   │
                   ├─ RadarTools 没有目标 → 检查软件配置和测试场景
                   └─ RadarTools 显示目标 → 连接完成
```

### 完成上述检查后仍然没有数据，应该提供哪些信息？

为便于进一步定位问题，建议记录：

* Windows 版本及设备管理器中的 USB-CAN FD 状态。
* RadarTools 版本、设备选择、通道选择及错误提示。
* 雷达线束标签与 CAN 端子的实际连接关系。
* 雷达侧供电测量结果。
* 是否能够接收到 CAN 数据。
* 测试目标、安装方向和现场遮挡情况。

提交问题时请隐藏设备序列号、个人目录和其他不需要公开的信息。

以上内容整理自一次实际的首次接线和排查过程。具体供电规格、通信参数、终端设置和软件选项，应以当前设备及当前版本官方文档为准。

### 点云采集后找不到数据文件？

请检查：

* 是否已经点击点云采集按钮。
* 是否点击 `Stop` 结束采集。
* `RadarTools/RadarTools_Release/data/` 目录是否存在。
* 上位机是否具有当前目录写入权限。

### ADC 采集后没有生成数据？

请检查：

* 是否已先点击 `Start`。
* ADC 采集界面参数是否已填写。
* 采集目录是否存在。
* 当前用户是否有写入权限。
* 雷达数据流是否正常输出。
* 远波 / 近波配置是否与采集设置一致。

### Matlab 分析 ADC 数据时报错？

请检查：

* ADC 数据是否已拷贝到 `ADC数据采集/matlab_signal_processing_platform_231023_for_txt_A100/data/`。
* 是否配置了正确的数据文件路径。
* 4 个接收通道文件名是否填写正确。
* 远波 / 近波配置文件是否选择正确。
* Matlab 当前工作路径是否在示例工程目录下。

###  Python 脚本运行时报缺少依赖？

请执行：

```bash
python -m pip install numpy pandas matplotlib scipy scikit-learn
```

脚本使用 SciPy 和 scikit-learn 实现目标跟踪与 DBSCAN 聚类。请完整安装上述依赖，否则相关功能无法正常使用。

若仍然报错，请确认当前终端使用的 Python 环境与安装依赖的 Python 环境一致。

###  Python 可视化没有显示结果？

请检查：

* 输入 CSV 路径是否正确。
* CSV 文件是否为空。
* 字段名是否与脚本中的读取字段一致。
* 数据中是否包含有效目标。
* matplotlib 是否正常安装。

### 标定结果异常怎么办？

请检查：

* 标定目标是否位于雷达有效视场内。
* 目标与雷达之间是否无遮挡。
* 周围是否有强反射物。
* 雷达和目标是否固定稳定。
* 标定工具是否使用正确版本。
* 是否在移动雷达后未重新标定。
