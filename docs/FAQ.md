### 首次连接 CTSAI-A100 后没有数据，应该按什么顺序排查？

首次连接时，建议按照“雷达供电 → CAN 接线 → 驱动识别 → RadarTools 配置 → 测试场景”的顺序排查。上一层没有确认之前，不要反复修改下一层参数。

```text
确认雷达供电
    │
    ├─ 供电异常 → 检查电源、极性、线束和接线端子
    │
    └─ 供电正常
         │
         ├─ Windows 未识别 USB-CAN FD → 检查驱动、USB 线和接口
         │
         └─ Windows 已识别
              │
              ├─ 没有 CAN 数据 → 检查 CAN-H/CAN-L、通道和接线
              │
              └─ 已有 CAN 数据
                   │
                   ├─ RadarTools 没有目标 → 检查软件配置和测试场景
                   └─ RadarTools 显示目标 → 连接完成
```

**安全提示：**剥线、重新插线或调整端子前，应先断开电源。不要让裸露导体相互接触，也不要触碰电源适配器的市电输入部分。线束用途应以标签和设备文档为准，不要只根据线的颜色判断。

更完整的接线和软件启动说明可参考：

* [设备连接与环境搭建](./产品简介/设备连接与环境搭建.md)
* [RadarTools 安装部署](./RadarTools/安装部署.md)

### 如何确认雷达已经正常供电？

USB-CAN FD 的电源或系统指示灯亮，只能说明 USB-CAN FD 本身已经工作，不能据此判断雷达是否已经获得供电。

请依次检查：

1. 确认使用的直流电源符合当前设备文档要求。
2. 根据线束标签确认电源正极和 `GND`，检查正负极是否接反。
3. 确认接线端子夹住的是导体而不是绝缘层，并轻拉线束检查是否松动。
4. 在熟悉万用表操作的前提下，使用直流电压档测量雷达侧电源正极与 `GND` 之间的电压。
5. 如果电源输出端正常而雷达侧没有电压，重点检查线束、端子和连接关系。

不同批次线束的标识可能存在差异，应以实物标签和当前设备文档为准。不要根据接线端子的外形推断内部导通关系；如需确认，应在断电状态下查阅端子说明或进行导通检查。

### 如何检查 CAN 接线？

请根据线束标签确认 CAN 信号，并检查以下事项：

* CAN-H 与 CAN-L 来自同一组通信信号，不要混用不同组的 H、L 信号。
* 雷达侧 CAN-H 连接 USB-CAN FD 对应通道的 H，CAN-L 连接对应通道的 L。
* 电源线没有误接入 CAN 端子。
* 多股导线已经可靠夹紧，没有散开的铜丝接触相邻端子。
* 实际接线通道与 RadarTools 中选择的 CAN 通道一致。

如果怀疑 CAN-H 与 CAN-L 接反，应先断电，再按照线束标签和端子标识重新确认。终端设置应遵循当前设备文档和实际总线连接方式，不要在缺少依据时反复切换。

### Windows 设备管理器看不到 USB-CAN FD 设备？

请检查：

1. USB-CAN FD 是否已经连接电脑。
2. USB 数据线是否能够正常传输数据。
3. 驱动安装程序是否与当前 Windows 系统匹配。
4. 设备管理器中是否存在未知设备或带黄色感叹号的设备。
5. 重新插拔设备或更换 USB 接口后，设备状态是否发生变化。

USB-CAN FD 的电源或系统指示灯正常，不等于 CAN 通信已经建立。是否存在通信，应结合设备管理器状态、CAN 通道状态和接收数据判断。

### USB-CAN FD 已被识别，但 RadarTools 仍然没有数据？

硬件和驱动确认正常后，请继续检查：

* RadarTools 是否选择了正确的 USB-CAN FD 设备。
* 软件选择的 CAN 通道是否与实际接线通道一致。
* 通信模式和参数是否来自当前版本的官方配置或已经验证的工程配置。
* 是否已经启动设备并开始接收数据。
* 软件是否报告设备打开、通道初始化或数据解析错误。

通信参数可能随固件、配置文件或软件版本变化，因此 FAQ 不固定给出具体数值。

可以进一步区分两种情况：

* **完全没有 CAN 数据：**返回检查雷达供电、CAN-H/CAN-L、设备通道和驱动状态。
* **已有 CAN 数据但没有目标：**重点检查 RadarTools 配置、数据类型和测试场景。

### RadarTools 能接收数据，但没有目标点？

首次验证时建议：

1. 让雷达正面朝向待测区域。
2. 确认雷达前方没有明显遮挡。
3. 让人员在雷达前方移动，作为容易观察的验证目标。
4. 确认目标位于当前安装方向覆盖的区域内。
5. 确认当前工作模式适合测试场景。

不要仅使用很小、完全静止或位置不明确的物体作为第一次验证目标。如果人员移动后仍没有目标，但软件已经能够接收 CAN 数据，应保存 RadarTools 配置和接收日志，再检查数据解析或雷达配置。

### 完成上述检查后仍然没有数据，应该提供哪些信息？

为便于进一步定位问题，建议记录：

* Windows 版本及设备管理器中的 USB-CAN FD 状态。
* RadarTools 版本、设备选择、通道选择及错误提示。
* 雷达线束标签与 CAN 端子的实际连接关系。
* 雷达侧供电测量结果。
* 是否能够接收到 CAN 数据。
* 测试目标、安装方向和现场遮挡情况。

提交问题时请隐藏设备序列号、个人目录和其他不需要公开的信息。

### 点云采集后找不到数据文件？

请检查：

* 是否已经点击点云采集按钮。
* 是否点击 `Stop` 结束采集。
* `tools/RadarTools_Release/data/` 目录是否存在。
* 上位机是否具有当前目录写入权限。

### ADC 采集后没有生成数据？

请检查：

* 是否已先点击 `Start`。
* ADC 采集界面参数是否已填写。
* 采集目录是否存在。
* 当前用户是否有写入权限。
* 雷达数据流是否正常输出。
* 远波 / 近波配置是否与采集设置一致。

### Matlab 分析 ADC 数据时报错？

请检查：

* ADC 数据是否已拷贝到 `examples/matlab-adc-processing/data/`。
* 是否配置了正确的数据文件路径。
* 4 个接收通道文件名是否填写正确。
* 远波 / 近波配置文件是否选择正确。
* Matlab 当前工作路径是否在示例工程目录下。

###  Python 脚本运行时报缺少依赖？

请执行：

```bash
python -m pip install pandas matplotlib numpy
```

若仍然报错，请确认当前终端使用的 Python 环境与安装依赖的 Python 环境一致。

###  Python 可视化没有显示结果？

请检查：

* 输入 CSV 路径是否正确。
* CSV 文件是否为空。
* 字段名是否与脚本中的读取字段一致。
* 数据中是否包含有效目标。
* matplotlib 是否正常安装。

### 标定结果异常怎么办？

请检查：

* 标定目标是否位于雷达有效视场内。
* 目标与雷达之间是否无遮挡。
* 周围是否有强反射物。
* 雷达和目标是否固定稳定。
* 标定工具是否使用正确版本。
* 是否在移动雷达后未重新标定。
